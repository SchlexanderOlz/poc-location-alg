Wie funktioniert das?

Problem: Mit LIMIT N, Zufallsauswahl oder „Top N nach Kapazität“ landen fast nur Punkte aus dichten Gebieten wie Wien auf der Karte, und der einsame Wanderparkplatz im Kaunertal fällt weg. Lädt man dagegen alles, wird der Browser bei vielen Punkten langsam.

Raster: Über den Ausschnitt wird ein Raster gelegt, dessen Zellen so groß sind, dass höchstens N davon sichtbar sind. Die Datenbank liefert pro belegter Zelle genau einen Repräsentanten (den mit der größten Kapazität) und die Anzahl der Punkte in der Zelle – also nie mehr als N Zeilen.

Ausreißer: Ein isolierter Punkt ist allein in seiner Zelle und damit automatisch ihr Repräsentant. Zusammengefasst wird nur, was auf dem Bildschirm ohnehin überlappen würde, und die Anzahl macht das sichtbar (größerer, oranger Kreis). Es fehlt nichts stillschweigend. Bei kleinem N auf großem Ausschnitt steckt ein Ausreißer zunächst in einer Gruppe und erscheint beim Hineinzoomen einzeln.

Stabile Zellen: Das Raster hängt an Weltkoordinaten (floor(lng / zellbreite)), nicht am Bildschirmrand, und die Zellgröße nur von Zoom und Fenstergröße. Nord-Süd wird in Web-Mercator-y gerechnet, damit die Zellen quadratisch sind. Beim Verschieben springen die Marker deshalb nicht.

WITH pts AS (
  SELECT id, latitude, longitude, capacity, name,
         floor(longitude / $5)::int                             AS cx,
         floor(ln(tan(pi()/4 + radians(latitude)/2)) / $6)::int AS cy
  FROM locations
  WHERE point(longitude, latitude) <@ box(point($1,$2), point($3,$4))
),
ranked AS (
  SELECT *,
         count(*)     OVER (PARTITION BY cx, cy)                            AS anzahl,
         row_number() OVER (PARTITION BY cx, cy ORDER BY capacity DESC, id) AS rn
  FROM pts
)
SELECT id, latitude, longitude, capacity, name, anzahl
FROM ranked
WHERE rn = 1
LIMIT $7;
